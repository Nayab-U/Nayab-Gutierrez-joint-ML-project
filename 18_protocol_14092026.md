# 🧠 Image Modelling with CNNs

## From Pixels to Prediction

This review explains the basic concepts behind **Artificial Neural Networks (ANNs)** and **Convolutional Neural Networks (CNNs)** for image data.

We will move step-by-step from:

**Pixels → Kernels → Edges → Feature Maps → CNN → Prediction**

---

### Main idea

```text
Raw pixels
    ↓
Kernels / filters
    ↓
Convolution
    ↓
Feature maps
    ↓
Edges → textures → shapes → object parts
    ↓
Prediction
```

---


## 1. ANN vs CNN

### What is an ANN?

**ANN = Artificial Neural Network**

An ANN is a neural network made of connected layers of neurons.

For image data, an ANN can receive the pixel values as numbers.

```text
Image

┌─────────┐
│ ░  ▓  ░ │
│ ▓  ▓  ▓ │
│ ░  ▓  ░ │
└─────────┘
     ↓
Pixel values
     ↓
[0, 128, 0, 255, 255, 255, ...]
     ↓
ANN
     ↓
Prediction
```

ANNs can learn nonlinear relationships and can be used for classification and regression.

However, when an image is converted into a long list of pixels, the ANN does not naturally understand that neighboring pixels belong together.

---

## 2. Why CNNs are useful for images

**CNN = Convolutional Neural Network**

CNNs are designed to work with spatial information.

Instead of immediately connecting every pixel to every neuron, a CNN looks at small local regions of the image.

```text
IMAGE
  ↓
small local region
  ↓
KERNEL
  ↓
CONVOLUTION
  ↓
FEATURE MAP
  ↓
learn edges
  ↓
learn textures
  ↓
learn shapes
  ↓
learn object parts
  ↓
PREDICTION
```

CNNs can automatically learn spatial features such as:

* Edges
* Textures
* Shapes
* Object parts
* Complex visual patterns

CNNs also use **parameter sharing**, meaning the same kernel can be used at different positions in the image.

---

## 3. ANN vs CNN — Quick Distinction

| ANN                                                   | CNN                                                     |
| ----------------------------------------------------- | ------------------------------------------------------- |
| General-purpose neural network                        | Designed especially for spatial data                    |
| Often uses fully connected layers                     | Uses convolutional layers                               |
| Image may be flattened into a vector                  | Keeps spatial structure                                 |
| Does not naturally exploit local pixel relationships  | Explicitly uses local pixel relationships               |
| Can require many connections for image data           | Parameter sharing reduces connections                   |
| Does not naturally detect the same feature everywhere | Same kernel can detect a feature at different positions |

### Easy memory trick

> **ANN:** "Give me the numbers."

> **CNN:** "Show me how the nearby numbers are arranged."

# Image Representation — Pixels

A computer does not see a photograph like a human does.

A grayscale image can be represented as a matrix of numbers.

```text
0   → black
255 → white
```

Values between them represent shades of gray.

```text
Black                         White
  0 -------------------------- 255
  │                             │
dark                          bright
```

Example:

```text
10   20   30   40
20   50   80   60
30   80  200  100
40   60  100  255
```

These numbers are the information that the neural network receives.

---

# Image Kernels / Filters

## What is a kernel?

A **kernel**, also called a **filter**, is a small matrix that moves across an image.

Its purpose is to detect or emphasize a particular pattern.

```text
IMAGE                       KERNEL

┌───────────────┐           ┌─────────┐
│               │           │ 1  0 -1 │
│               │     +     │ 1  0 -1 │
│               │           │ 1  0 -1 │
└───────────────┘           └─────────┘
```

The kernel looks at a small area of the image at a time.

---

# How Does Convolution Work?

The basic process is:

1. Put the kernel over a small image region.
2. Multiply corresponding numbers.
3. Add all the results.
4. Move the kernel.
5. Repeat.

### Example

Image region:

```text
1  2  3
4  5  6
7  8  9
```

Kernel:

```text
1  0 -1
1  0 -1
1  0 -1
```

Multiply corresponding values:

```text
1×1   2×0   3×(-1)
4×1   5×0   6×(-1)
7×1   8×0   9×(-1)
```

Then add:

```text
1 + 0 - 3
+ 4 + 0 - 6
+ 7 + 0 - 9
```

Result:

```text
-6
```

The kernel then moves to another location and performs the same calculation.

---

# Vertical Edge Detection

One important use of a kernel is detecting **edges**.

An edge is an area where the image intensity changes sharply.

A simple vertical-edge kernel is:

```text
┌─────────────┐
│  1   0  -1  │
│  1   0  -1  │
│  1   0  -1  │
└─────────────┘
```

### What does it mean?

```text
LEFT       MIDDLE       RIGHT

 +1           0           -1
  ↑           ↑            ↑
look here   ignore       look here
```

The middle column has `0`, so it contributes nothing.

The kernel compares the left side with the right side.

If there is a large difference, the result has a large magnitude.

```text
Similar left/right
        ↓
small result
        ↓
weak or no vertical edge
```

```text
Very different left/right
        ↓
large result
        ↓
strong vertical edge
```

---

# Visual Example — Vertical Edge

Imagine an image with a dark region next to a bright region:

```text
DARK             BRIGHT

████████│░░░░░░░░
████████│░░░░░░░░
████████│░░░░░░░░
████████│░░░░░░░░
         ↑
    vertical edge
```

The kernel detects the sharp change between the two regions.

# Feature Map

The output created after applying a kernel across an image is called a **feature map**.

```text
Original image
      ↓
    Kernel
      ↓
 Convolution
      ↓
 Feature map
```

The feature map shows where the detected feature appears.

Example:

```text
Original image          Feature map

████░░░░                 0  0  8  0
████░░░░        →        0  0  9  0
████░░░░                 0  0  8  0
████░░░░
```

Large values can indicate locations where the kernel strongly detected the feature.

# Image Feature Engineering

Before CNNs became widely used, computer vision often relied on **hand-crafted features**.

Instead of asking the model to learn everything from raw pixels, humans designed methods for extracting useful information.

```text
IMAGE
  ↓
Feature engineering
  ↓
HOG / SIFT / SURF
  ↓
Machine Learning model
  ↓
Prediction
```

Important traditional methods:

* Edges
* HOG
* SIFT
* SURF

---

# Edges

Edges represent strong changes in image intensity or color.

```text
████████│░░░░░░░
████████│░░░░░░░
████████│░░░░░░░
         ↑
        edge
```

Edges can help describe the boundaries of objects.

---

# HOG

**HOG = Histogram of Oriented Gradients**

HOG describes the **directions of edges** in an image.

Think about different edge directions:

```text
↗    ↑    ↖

←    •    →

↘    ↓    ↙
```

HOG captures information about the orientation of image gradients.

### Easy memory trick

> **HOG = Which direction are the edges pointing?**

---

# SIFT

**SIFT = Scale-Invariant Feature Transform**

SIFT identifies distinctive points such as:

* Corners
* Blobs
* Other distinctive local structures

It is designed to be robust to changes such as scale and rotation.

### Easy memory trick

> **SIFT = Find distinctive points.**

---

# SURF

**SURF = Speeded-Up Robust Features**

SURF is another traditional feature-detection approach with a similar purpose to SIFT, but designed to be faster.

### Quick comparison

| Method | Main idea                                |
| ------ | ---------------------------------------- |
| Edges  | Find sharp changes                       |
| HOG    | Describe edge directions                 |
| SIFT   | Find distinctive keypoints               |
| SURF   | Similar idea to SIFT, designed for speed |
| CNN    | Learns useful features automatically     |

---

# Automatic Feature Learning

A CNN can transform a large collection of raw pixel values into a more useful feature representation.

```text
RAW IMAGE

[pixels][pixels][pixels]
[pixels][pixels][pixels]
[pixels][pixels][pixels]

        ↓

LEARNED FEATURES

[edges]
[textures]
[shapes]
[parts]

        ↓

FEATURE VECTOR

[0.12, 0.87, 0.04, ...]

        ↓

PREDICTION
```

### Key idea

> **Raw pixels → learned features → compact representation → prediction**

# Why Not Just Use a Normal DNN?

Suppose we have:

```text
1  0
0  1
```

Now move the pattern:

```text
0  1
1  0
```

The same basic pattern exists, but the pixel positions changed.

A fully connected network receives something like:

```text
x1  x2  x3  x4
```

It does not naturally know that neighboring pixels belong together.

A CNN instead looks at **local neighborhoods**.

```text
┌─────────┐
│ nearby  │
│ pixels  │ ← kernel
│ together│
└─────────┘
```

This helps CNNs recognize patterns when their position changes within an image.

---

# Padding

When a kernel moves across an image, we can add extra pixels around the border.

This is called **padding**.

Original:

```text
1 2 3
4 5 6
7 8 9
```

With zero padding:

```text
0 0 0 0 0
0 1 2 3 0
0 4 5 6 0
0 7 8 9 0
0 0 0 0 0
```

### Why use padding?

* Preserve spatial dimensions
* Avoid losing too much border information
* Allow deeper CNNs without shrinking the image too quickly

Two common settings:

```text
padding="valid"
→ no padding

padding="same"
→ padding is added to maintain spatial size
```

---

# Stride

**Stride = how far the kernel moves each time.**

### Stride = 1

```text
[###] →
  [###] →
    [###] →
```

The kernel moves one pixel at a time.

### Stride = 2

```text
[###]   →→
    [###]   →→
```

The kernel jumps two pixels.

### Effect

```text
larger stride
      ↓
fewer positions
      ↓
smaller feature map
      ↓
less computation
```

---

# Pooling

Pooling reduces the size of a feature map.

Two important types:

* Max pooling
* Average pooling

---

# Max Pooling

Max pooling takes the largest value.

Example:

```text
2  8
3  5
```

Maximum:

```text
8
```

Visual:

```text
┌───────┐
│ 2  8  │
│ 3  5  │
└───────┘
     ↓
     8
```

---

# Average Pooling

Average pooling calculates the average.

```text
2  8
3  5
```

Calculation:

```text
(2 + 8 + 3 + 5) / 4

= 18 / 4

= 4.5
```

Visual:

```text
┌───────┐
│ 2  8  │
│ 3  5  │
└───────┘
     ↓
    4.5
```

Pooling helps reduce:

* Spatial dimensions
* Computation
* Memory usage

It can also provide some robustness to small translations or shifts.

# Stationarity & Weight Sharing

## Stationarity

The same type of feature can appear **anywhere in an image**.

For example, a vertical edge might appear in different positions:

```text
LEFT             CENTER             RIGHT

████│░░░░        ░░████│░░        ░░░░████│
    ↑                ↑                  ↑
same type of vertical edge
```

The important feature is the edge itself, not its exact position.

---

## Weight Sharing

The **same kernel** can scan the entire image.

```text
             SAME KERNEL
                  ↓

┌─────────────────────────┐
│ [###]                   │
│                         │
│          [###]          │
│                         │
│                    [###]│
└─────────────────────────┘
```

This reduces the number of parameters and makes CNNs efficient.

---

# Compositionality

CNNs learn increasingly complex patterns by combining simpler patterns.

Think of it like building with LEGO:

```text
PIXELS
  ↓
EDGES
  ↓
TEXTURES / SIMPLE PATTERNS
  ↓
OBJECT PARTS
  ↓
COMPLETE OBJECT
```

For example, for a face:

```text
pixels
  ↓
edges
  ↓
eyes + nose + mouth
  ↓
face structure
  ↓
FACE
```

### Easy memory trick

> **Simple features combine to create complex features.**

This is called **compositionality**.

# ReLU

**ReLU = Rectified Linear Unit**

ReLU is an **activation function**.

It is commonly placed after a convolution or dense layer.

The formula is:

```text
ReLU(x) = max(0, x)
```

That means:

```text
negative
```
